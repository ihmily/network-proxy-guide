# 第11章 一键脚本部署

本章给出Xray官方安装器、mack-a、233boy和WireGuard脚本的项目地址、安装命令与管理步骤。先按用途选工具，再完成备份、安装和连通性验证；**只安装Xray-core不会自动生成可用节点**，协议配置见第12章。

| 项目 | 项目地址 | 用途 | 操作位置 |
|---|---|---|---|
| Xray官方安装器 | [XTLS/Xray-install](https://github.com/XTLS/Xray-install) | 安装Xray-core，配置需自行完成 | 11.2 |
| mack-a v2ray-agent | [mack-a/v2ray-agent](https://github.com/mack-a/v2ray-agent) | 交互式安装Xray、多协议组合 | 11.3.1 |
| 233boy Xray | [233boy/Xray](https://github.com/233boy/Xray) | Xray交互式安装与管理 | 11.3.2 |
| WireGuard installer | [angristan/wireguard-install](https://github.com/angristan/wireguard-install) | WireGuard服务端与客户端配置 | 11.3.3 |
| 3X-UI | [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui) | Web面板和多用户管理 | [第13章](第13章-多用户管理方案.md) |
| Trojan-Go | [p4gefau1t/trojan-go](https://github.com/p4gefau1t/trojan-go) | 官方发布包与配置 | [第12章](第12章-手动搭建教程.md) |

## 11.1 执行前的核对与备份

### 11.1.1 确认来源和适用环境

从项目官方仓库或官方网站找到安装说明，核对仓库所有者、最近的发布记录、适用系统和所需权限。不要仅凭脚本名称、转发链接或GitHub Star数量判断可信度。确认它是否会安装其他组件、开放端口、修改防火墙、写入定时任务或上传诊断信息；无法理解的操作先在隔离测试机中验证。

记录以下信息，便于复现与回退：

| 项目 | 记录内容 |
|------|----------|
| 系统 | 发行版、版本、架构及当前更新状态 |
| 来源 | 官方项目地址、脚本下载地址、取得日期 |
| 版本 | 脚本提交或发布标记、待安装软件版本 |
| 变更 | 预期新增的服务、文件、端口和定时任务 |
| 恢复 | 云平台快照、原配置备份、控制台登录路径 |

### 11.1.2 保留恢复路径

先创建服务器快照或完整备份，并确认能通过云控制台恢复。保留一个可用的SSH会话；修改SSH、防火墙或路由前，另开会话验证新设置。不要在唯一管理通道中直接试运行未知脚本。涉及已有业务的服务器，应先在独立测试环境演练。

## 11.2 Xray官方安装脚本示例

### 11.2.1 一键安装与下载检查

以[XTLS/Xray-install项目仓库](https://github.com/XTLS/Xray-install)为例。以下命令面向具有`curl`、`bash`、`sha256sum`和`systemd`的Linux环境；运行前仍要对照仓库当前说明。脚本使用仓库的`main`分支，内容可能变化；需要可复现部署时，应改用经过核对的固定提交或发行版本，并记录其摘要。

**项目README提供的快捷安装命令：**

```bash
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install
```

想先查看脚本内容，可按下面的下载方式安装。

```bash
# 在测试机上的独立目录操作；确认下载成功后才继续
mkdir -p "$HOME/xray-install-review"
cd "$HOME/xray-install-review"
curl -fL --show-error \
  https://raw.githubusercontent.com/XTLS/Xray-install/main/install-release.sh \
  -o install-release.sh

# 记录本次取得的文件；摘要只有与可信来源公布的值比对才构成来源校验
sha256sum install-release.sh
bash -n install-release.sh
less install-release.sh
```

`bash -n`只检查Shell语法，不证明脚本安全。审阅时特别留意额外下载、提权、系统配置替换、网络回传与清理行为。若脚本还会下载其他文件，应继续核对其来源和完整性。不要关闭TLS证书校验，也不要将远程响应直接通过管道送入Shell。

| 审查位置 | 要查的问题 | 不满足时的处理 |
|----------|------------|----------------|
| 下载命令 | 是否使用项目维护者控制的地址，是否有重定向和额外下载 | 停止执行，追踪每个实际下载目标 |
| 系统修改 | 是否创建服务用户、改防火墙、证书或系统设置 | 与预期变更清单对照并准备恢复 |
| 凭据 | 是否打印、上传或写入可被其他用户读取的文件 | 修改处理方式或不用该脚本 |
| 自动更新 | 是否会在以后以高权限获取新的代码 | 关闭或纳入独立审查与维护计划 |

对从`main`分支下载的文件，记录哈希只便于日后确认“执行的是哪一份”，不证明文件由可信发布者签发。若发布者提供签名或校验值，应通过独立的可信渠道比对；没有提供时，应明确这一验证缺口。

确认来源、内容、版本和备份后，再按照仓库当前文档选择安装参数。以下是**流程示意**，执行前应查看脚本帮助和项目文档；不要在未审阅脚本时直接复制最后一行：

```bash
bash ./install-release.sh help
# 确认帮助输出中的 install 语法与预期版本后：
sudo bash ./install-release.sh install
```

### 11.2.2 验证安装边界

安装后核对实际软件版本、服务单元、监听端口与日志，不预设脚本一定生成可用的服务端配置：

```bash
xray version
systemctl cat xray
systemctl status xray --no-pager
ss -lntup
journalctl -u xray -n 50 --no-pager
```

服务未启动时先看日志和配置检查结果，不要盲目关闭防火墙或扩大公网开放范围。服务端与客户端配置、证书及连通性检查见[第12章 手动搭建教程](第12章-手动搭建教程.md)；入口安全与权限设置见[第14章 网络安全防护](../第五部分-安全与隐私篇/第14章-网络安全防护.md)。

| 现象 | 先检查 | 避免的误操作 |
|------|----------|--------------|
| 命令不存在 | 安装输出、实际路径与Shell环境 | 反复运行未经审阅的新脚本 |
| 服务启动失败 | `systemctl status`和最近日志、配置语法 | 直接放开所有端口 |
| 服务运行但客户端不通 | 监听地址、云防火墙、证书、客户端参数 | 只凭“active”状态判定部署完成 |
| 更新后失联 | 版本、配置差异、原有快照与控制台 | 在唯一SSH会话中继续试错 |

### 11.2.3 安装路径与基础管理

安装器README列出的常见路径如下，实际以`systemctl cat xray`显示的服务参数和安装输出为准：

| 用途 | 路径 |
|---|---|
| 可执行文件 | `/usr/local/bin/xray` |
| 配置目录 | `/usr/local/etc/xray/` |
| 默认配置文件 | `/usr/local/etc/xray/config.json` |
| 日志目录 | `/var/log/xray/` |
| systemd服务 | `/etc/systemd/system/xray.service` |

**VLESS + TLS示例：** 先准备指向服务器的域名及有效证书，用`xray uuid`生成UUID；把下面的占位值替换后写入`/usr/local/etc/xray/config.json`。证书和私钥文件必须存在，并允许Xray服务账号读取。

```json
{
  "log": {"loglevel": "warning"},
  "inbounds": [{
    "port": 443,
    "protocol": "vless",
    "settings": {
      "clients": [{"id": "REPLACE_WITH_UUID"}],
      "decryption": "none"
    },
    "streamSettings": {
      "network": "tcp",
      "security": "tls",
      "tlsSettings": {
        "certificates": [{
          "certificateFile": "/path/to/fullchain.pem",
          "keyFile": "/path/to/privkey.pem"
        }]
      }
    }
  }],
  "outbounds": [{"protocol": "freedom"}]
}
```

```bash
# 生成客户端UUID，填入你自己的服务端配置
xray uuid

# 编辑配置后先验证语法，再启动服务
sudo nano /usr/local/etc/xray/config.json
sudo xray run -test -config /usr/local/etc/xray/config.json
sudo systemctl enable --now xray
systemctl status xray --no-pager
journalctl -u xray -n 50 --no-pager
```

客户端使用相同的域名、443端口、UUID、VLESS协议与TLS设置导入；先通过上面的配置检查命令再启动服务。Reality、证书准备和其他入站参数见[第12章 手动搭建教程](第12章-手动搭建教程.md)。

## 11.3 常见社区脚本与面板

以下脚本有各自的菜单和协议组合，不共用同一套命令。先按表格选择项目，再依照对应小节操作。

### 11.3.1 mack-a v2ray-agent

项目README的入口为`master/install.sh`。下面是Ubuntu/Debian示例，用`curl`下载到本地，不使用README里的`--no-check-certificate`选项：

```bash
sudo apt update
sudo apt install -y curl wget
sudo curl -fL --show-error \
  https://raw.githubusercontent.com/mack-a/v2ray-agent/master/install.sh \
  -o /root/v2ray-agent-install.sh
sudo bash -n /root/v2ray-agent-install.sh
sudo bash /root/v2ray-agent-install.sh
```

进入菜单后选择安装类型，再按提示选择VLESS + Reality或需要域名、证书的TLS组合。安装完成时保存生成的客户端链接或二维码，用测试客户端导入并验证。日后运行`sudo bash /root/v2ray-agent-install.sh`进入管理菜单；更新脚本前重新从仓库核对来源。

### 11.3.2 233boy Xray

当前项目为[233boy/Xray](https://github.com/233boy/Xray)，不要照搬旧版`233boy/v2ray`的短网址安装入口。作者的[使用文档](https://233boy.com/xray/xray-script/)链接到以下脚本。当前脚本内有跳过证书验证的`wget`调用，先审阅其后续下载逻辑，再决定是否执行。

```bash
curl -fL --show-error \
  https://raw.githubusercontent.com/233boy/Xray/main/install.sh \
  -o 233boy-xray-install.sh
bash -n 233boy-xray-install.sh
less 233boy-xray-install.sh
sudo bash ./233boy-xray-install.sh
```

安装后以脚本实际显示的管理命令查看账号、状态和日志。

### 11.3.3 WireGuard installer

[Angristan脚本](https://github.com/angristan/wireguard-install)的README提供以下下载与运行方式：

```bash
curl -fL --show-error \
  https://raw.githubusercontent.com/angristan/wireguard-install/master/wireguard-install.sh \
  -o wireguard-install.sh
chmod 700 wireguard-install.sh
sudo ./wireguard-install.sh
```

按菜单填写监听端口、客户端名称与地址，脚本会生成服务端配置和第一个客户端文件。保存客户端配置后核对`sudo wg show`、`systemctl status wg-quick@wg0 --no-pager`，并从客户端验证握手和路由。需要图形界面时，可另查[WireGuard-UI项目](https://github.com/ngoduykhanh/wireguard-ui)的Docker Compose示例；不要沿用旧教程里的固定`admin/password`凭据。

### 11.3.4 Trojan-Go与管理面板

Trojan-Go的安装入口是[项目发布页](https://github.com/p4gefau1t/trojan-go/releases)；本书的[第12章手动搭建教程](第12章-手动搭建教程.md)给出配置与systemd示例。选择第三方菜单脚本时，先核对它实际安装的是Trojan-Go、Trojan-GFW还是其他实现，避免把不同项目的命令混用。

3X-UI面板的安装、初始账号和管理入口见[第13章](第13章-多用户管理方案.md)。面板首次登录前限制管理端口的访问范围，设置独立凭据，并备份用户与入站配置。

## 11.4 验证、更新与回退

### 11.4.1 最小验收清单

1. 软件版本、配置检查和服务状态符合预期；只开放确实需要的端口。
2. 使用测试客户端验证握手、DNS、分流及目标服务的实际请求，不只看脚本打印的二维码。
3. 检查新增用户、服务、定时任务和监听端口，确认无未计划的变更。
4. 将密钥、订阅链接和日志放在受限位置，避免写入公开仓库或排障截图。
5. 记录安装来源、脚本摘要、软件版本、变更清单和回退方法。

### 11.4.2 更新与故障恢复

更新前阅读发布说明并备份可用配置，在测试机复现升级，再逐步应用到正式环境。更新安装脚本和更新代理核心是不同操作；脚本本身变化也需重新审阅。若升级后失联，通过云控制台或保留的SSH会话回退配置或快照，并在恢复后重新检查端口、证书和客户端连接。

在正式变更前至少演练一次：用测试机导出配置，执行升级，再恢复原版本和配置；记录恢复耗时、遗漏文件与仍需人工处理的步骤。没有经过恢复验证的快照，只能算潜在备份，不能算已证明可回退。

## 本章小结

本章介绍了Xray官方安装器、mack-a、233boy和WireGuard脚本的项目入口与安装步骤。官方安装器负责Xray核心；交互脚本和面板可进一步生成协议与用户配置，但最终仍要检查服务状态、监听端口和客户端连接。

**实践任务：**

1. 从开头的项目表选择一种工具，在测试VPS上记录仓库地址、脚本版本和系统信息。
2. 创建快照，按对应小节安装并记录菜单选择或配置文件路径。
3. 检查服务状态、监听端口和日志，再从测试客户端导入配置并验证实际请求。
4. 导出配置，演练一次更新或回退，确认用户与节点信息可以恢复。
