    第9章 VPS选购指南¶

    买VPS主要比较供应商、机房线路、配置与流量、IP质量和总成本。本章提供配置样例、购买流程与测试命令；价格、库存和支付方式以实际结算页为准。

    9.1 VPS供应商对比¶

    9.1.1 先比较适用条件¶

    不要只按最低月费排序。先从供应商的官方产品、服务条款和支持页面核对以下项目：

    维度 应核对的问题
    使用范围 所需业务是否符合可接受使用政策；是否允许相关端口与流量类型
    实例资源 CPU、内存、存储、架构及超售或共享资源说明
    网络与流量 端口速率、出站额度、计费方式、超额后的处理、IPv4/IPv6支持
    运维能力 控制台、重装、快照、备份、监控、故障支持与状态页
    账号与合同 身份核验、支付方式、续费、退款、关停和数据删除条款
    地域与数据 机房位置、数据驻留要求、访问路径与所需服务条款

    常见供应商： 先从产品页确定候选机房与配置，再在结算页比较实际价格和流量规则。

    供应商 官方入口 选购时重点看
    Vultr Cloud Compute 机房、出站额度、实例删除后的计费
    DigitalOcean Droplets 机房、流量池、快照与备份费用
    Akamai / Linode Essential Compute 机房、共享资源规格与出站计费
    BandwagonHost（搬瓦工） 官网 具体线路、库存、续费与迁移条款
    Hostwinds Linux VPS 带宽政策、备份、IP更换条件
    AWS Lightsail 定价页 套餐内流量、超额计费与区域

    网站上的基准测试、广告中的“优化线路”和用户评价可作为线索，但不能替代从自己接入网络做实际测量。对没有官方价格、流量条款或退款说明的候选项，不应根据第三方列表作采购决定。

    9.1.2 计算可比的总成本¶

    按同一币种和同一使用周期计算：

    预计总成本 = 实例租金 + 超额流量 + 备份/快照 + 附加IP或存储 + 税费与支付费用

    记录促销结束后的续费价格，以及停机、销毁或迁移期间是否继续收费。长期承诺只有在使用规模、网络质量和退出条件已经验证后才有意义。付费前保存当时的价格和条款页面，日后对账与续费时重新核对。

    9.1.3 注册与购买流程¶

    以Vultr购买流程为例，可按以下顺序检查；控制台按钮名称可能变化，以结算页为准。

    1. 从官方入口注册，验证邮箱，并先启用双因素认证；准备SSH公钥。
    2. 创建Cloud Compute实例，依次选择 机房、操作系统、CPU/内存、磁盘和流量套餐。首次试用优先选可按需销毁、可扩容的规格。
    3. 在确认页记录实例月费或小时费、超额流量价格、快照/备份费用、续费与退款条件，再付款或启用实例。
    4. 实例变为可运行后保存控制台入口、IP、系统版本与SSH密钥位置；先测试SSH及目标端口，不要把随机生成的初始密码发到聊天群。
    5. 用自己常用的网络在高峰和非高峰时段测试。若IP或线路不合适，先查清重建、换IP和销毁规则，再决定是否保留。

    9.2 地域选择策略¶

    9.2.1 从实际路径测量¶

    机房距离只是影响体验的因素之一。客户端接入网络、运营商互联、拥塞时段、目标服务所在地和分流规则，都可能改变结果。先向服务商索取其官方测试地址或测试文件，并在自己常用的网络与时段测量；不要把文档示例IP当作真实服务器。

    测试 用途 解释边界
    ping 观察测试目标的往返时间与丢包 ICMP可能被限制，单次超时不能证明服务不可用
    traceroute / mtr 观察路径变化 中间跳点的丢包不一定是端到端丢包
    受控下载/上传 在授权端点估算实际吞吐 会消耗流量，结果受目标和时段影响
    实际业务请求 验证目标服务与所选出口 需同时检查DNS、规则和服务条款

    机房延迟初筛： 下面是从中国大陆接入时的粗略经验区间，用来决定先测哪些机房；具体结果仍取决于运营商和时段。

    机房 经验参考RTT 首先关注
    香港 5–30 ms 低延迟、跨运营商拥塞和价格
    日本、韩国 30–80 ms 晚高峰路由和丢包
    新加坡 50–100 ms 东南亚互联及回程
    美国西部 130–180 ms 跨洋路由与目标服务区域
    美国东部 180–230 ms 更长的跨洋路径
    欧洲 250–350 ms 特定地域需求和稳定性

    从常用网络对服务商提供的测试地址运行ping和traceroute（Windows用tracert）；已安装mtr时可用mtr -rwzc 30 TEST_HOST（替换为实际测试地址）观察多次探测结果。记录运营商和测试时段，再比较不同机房。

    测试时记录来源网络、日期、时段、目标、协议和节点配置。至少比较高峰与非高峰时段，并留意稳定性，而不是仅取最高速度。

    一个可重复的小规模测试计划是：先在常用设备上记录不经过候选VPS的基线，再在同一设备、同一网络和相近时段测试候选服务商的官方测试端点；重复测量后比较中位表现与异常次数。变更接入网络、测试目标或客户端规则时，另开一组记录，不把不同条件下的数字直接排名。吞吐测试前确认测试文件大小与剩余流量，避免为比较机房产生意外费用。

    9.2.2 线路类型与机房筛选¶

    “普通线路、CN2 GT/GIA、BGP多线”是选购时常见的标签。采购前分别从电信、联通、移动或自己的实际接入网络测回程路径和高峰表现。

    线路标签 常见含义 应核对的证据
    普通国际转接 经公共骨干和国际运营商互联 高峰RTT、丢包、实际路径
    CN2 GT / GIA 电信CN2相关产品，覆盖范围和方向因套餐而异 服务商线路说明、来回程路由、测试IP
    BGP多线 机房接入多个运营商并选择路由 你的运营商是否真的走更合适的路径

    机房初筛可按用途进行：低延迟交互优先测试相近区域；面向特定地域的业务先确认目标服务区域；预算敏感时比较普通线路与优化线路的高峰差异。不要只因机房地理距离近或宣传“CN2”就直接购买长期套餐。

    9.2.3 同时考虑数据和服务要求¶

    工作资料、客户信息或个人信息可能有地域与跨境处理要求；目标服务也可能限制数据中心地址或账号的使用方式。先确定合法和合同允许的范围，再在范围内比较网络表现。机房标签与IP地理数据库可能不完全一致，不能用地区名称推定某项服务一定可用。

    9.3 配置需求分析¶

    9.3.1 从最小工作负载开始¶

    列出预期的同时在线连接、应用协议、日志保留、系统和证书需求。个人使用可从以下配置筛选，再根据实际负载决定是否扩容：

    场景 CPU / 内存 存储 月流量额度 适用情况
    单人轻度 1 vCPU / 1 GB 20–25 GB SSD 500 GB–1 TB 网页、文档和少量视频
    单人重度 1–2 vCPU / 2 GB 50 GB SSD 约2 TB 多设备、高清视频或较多下载

    视频是否流畅主要取决于实际线路、端口限速和目标服务，不由CPU、内存数字单独保证。初次测试可选可扩容、可取消的方案；长期运行前观察CPU、内存、磁盘和网络使用情况。

    资源 观察方法 扩容信号
    CPU 使用率与负载的持续趋势 高峰时长时间饱和，延迟随负载上升
    内存 可用内存、交换与进程终止记录 频繁交换或因内存不足退出
    存储 可用空间、日志与备份增长 接近容量上限或无法完成备份
    网络 出站总量、丢包和吞吐 超额、持续排队或不稳定

    9.3.2 多人共享配置¶

    多人共享可按下表选择初始配置。它是 容量样例，不是某家服务商的实时套餐；同时在线视频和下载会改变实际负载。

    使用人数 CPU / 内存 存储 月流量额度 网络端口 管理重点
    2–5人 2 vCPU / 4 GB 80 GB SSD 3–4 TB 1 Gbps 在3X-UI为每人设独立客户端、流量与到期时间
    5–10人 4 vCPU / 8 GB 160 GB SSD 5–6 TB 1 Gbps 分配配额，观察高峰带宽、CPU、内存与丢包

    表中的流量额度偏宽裕，不是最低需求；按9.3.3算出的实际用量较低时，可以选择更小的套餐。

    端口标称1 Gbps不等于可持续跑满；先确认供应商的共享带宽和公平使用条款。试用或短期购买后，在目标人数同时使用时查看top、free -h和ss -s，再决定是否升级。每个用户使用独立标识，出现异常流量时才能定位和限制；面板设置见第13章 多用户管理方案。

    9.3.3 流量计算¶

    按真实业务测得的日均出站量、预计使用天数和峰值波动估算，而非按客户端显示的连接数推算。注意云服务商可能按服务器出站流量计费，客户端与服务器两端的统计口径也可能不同。将系统更新、备份和测速流量纳入预算，并核对超额规则。

    活动 粗略消耗 月度估算例子
    普通网页 约1–3 MB/页；图片较多可到5–10 MB/页 100页/天 × 5 MB ≈ 15 GB/月
    720p视频 约1.5 GB/小时 1小时/天 ≈ 45 GB/月
    1080p视频 约3 GB/小时 2小时/天 ≈ 180 GB/月
    4K视频 约7 GB/小时 1小时/天 ≈ 210 GB/月
    文件下载 按文件实际大小 一次20 GB下载就占用20 GB额度

    编码、码率、自动播放和客户端缓存会使实际消耗变化。先按使用习惯计算，再乘以1.2–1.5的余量；连续运行后用服务商账单和面板计数校正。

    预计月出站量 = 每人日均出站量 × 人数 × 使用天数 × 峰值余量系数
示例：4人 × 5 GB/天 × 30天 × 1.25 = 750 GB/月

    9.3.4 性能测试¶

    优先使用系统监控和服务商提供的测试端点。运行第三方基准脚本前，按照第11章的脚本审查流程核对来源、版本与行为；不要直接复制“下载后立即执行”的命令。高强度磁盘或网络测试可能影响已有业务并产生额外费用，须在可控时段与授权环境中进行。

    # 基础资源与连接检查（Linux）
lscpu
free -h
df -h
ss -s

# 观察运行中CPU、内存和网络接口计数
top
ip -s link

    若要测试磁盘I/O或跨地域吞吐，先备份业务数据，记录测试文件大小和服务商流量计费方式；结果至少与另一个时段复测比较。

    9.4 付款方式与隐私保护¶

    9.4.1 核对支付和账号条款¶

    支付方式以服务商当前结算页面为准。比较汇率、手续费、续费、发票、退款及争议处理；不要为了回避服务商的身份核验而使用虚假身份或不可恢复的邮箱。账号应使用独立强密码和多因素认证，妥善保存账单与恢复信息。

    方式 使用时核对 常见取舍
    银行卡/信用卡 预授权、自动续费、外币手续费与消费提醒 覆盖广，但要管理账单和卡片风险
    PayPal 商户是否支持、账户地区、汇率和争议规则 可减少向每个商户直接提供卡号
    支付宝/微信支付 当前商户及地区是否提供、退款路径 操作方便，支付记录与账户关联
    加密货币 实际到账金额、网络手续费、退款方式 转账通常不可撤销，链上交易不等于匿名

    9.4.2 控制数据暴露¶

    确认服务商的隐私政策、日志与数据保留说明，以及关停实例后的删除流程。代理服务器可能接触连接元数据，支付记录也可能与账号关联；任何支付方式或注册地区都不能单独保证匿名。需要处理他人信息时，先满足组织和适用法律要求。

    9.4.3 账号安全¶

    1. 为VPS控制台使用独立密码，并启用认证器或安全密钥形式的双因素认证。
    2. 将密码保存在密码管理器，例如Bitwarden或KeePass；不要把示例密码直接用作真实密码。
    3. 离线保存2FA恢复码，测试备用登录方法，避免丢失手机后无法管理或销毁实例。
    4. 创建实例时优先添加SSH公钥；若供应商发放初始密码，首次登录后更换并检查控制台访问记录。
    5. 开启账单通知，定期检查未使用的实例、快照、附加IP和自动续费。

    9.5 IP质量检测¶

    9.5.1 IP类型与信誉¶

    在IPinfo查看IP的ASN、运营机构和地区，再与服务商告知的机房信息核对。ASN属于数据中心并不表示IP不能使用；ASN显示为住宅网络也不能单独证明它是真实住宅IP。地区数据库可能更新滞后，应以目标业务的实际表现为准。

    如果要从VPS发送邮件，可在MXToolbox黑名单查询检查邮件相关RBL记录；“Listed”主要提示邮件投递风险，不能直接推断代理连接或流媒体一定失败。

    9.5.2 连通性与端口测试¶

    先确认VPS运行、服务监听，再从本地测TCP；只看到ping超时，不能断定IP不可用。

    # 在VPS上：确认服务是否监听预期端口
sudo ss -lntup

# 在自己的Linux/macOS设备上：替换地址和端口
nc -vz YOUR_VPS_IP 443

# 若已配置自己的HTTPS测试域名，再核对TLS和HTTP响应
curl -v --connect-timeout 5 https://YOUR_TEST_DOMAIN/

    Windows可用PowerShell执行Test-NetConnection YOUR_VPS_IP -Port 443。若失败，按“服务未监听 → 云防火墙 → 系统防火墙 → 本地网络/路由”的顺序检查；从另一网络复测并记录时间。不要在尚未启动服务时，用外部端口检测站的“关闭”结果判断IP有问题。详细命令见第18章 网络测试工具。

    9.5.3 目标服务可用性¶

    目标网站是否接受数据中心IP，应在符合其条款的前提下，用实际账户和客户端验证。对Netflix等流媒体，仅执行curl -I或第三方“解锁脚本”不能证明播放权限；地区、账号、版权与设备条件都可能影响结果。将目标服务测试与VPS的TCP连通、路由稳定性分开记录。

    9.5.4 采购前决策记录¶

    项目 记录内容
    连通性 SSH、所需TCP端口、TLS及实际请求结果
    线路 高峰和非高峰的RTT、丢包与路由变化
    IP信息 ASN、地区、邮件黑名单和目标服务实测
    成本 当前租金、超额流量、备份、续费与退出费用
    运维 控制台恢复、快照、换IP与客服响应路径

    把候选项和测试结果记录在采购笔记中。如果IP或线路只有单次测试结果，先用短期方案验证，再决定是否长期续费。

    本章小结¶

    先用供应商、地域、配置和流量示例缩小范围，再以当前产品页、结算页和自己的网络测试结果做最终选择。

    1. 从9.1的供应商表选两个候选，记录机房、CPU/内存、流量、续费价与官方条款。
    2. 按9.3计算单人或多人月流量，核对套餐额度和超额收费。
    3. 在高峰和非高峰时段，从自己的网络测试供应商提供的端点。
    4. 若已购买短期实例，按9.5检查端口、IP信息和目标服务，并记录测试结果。
